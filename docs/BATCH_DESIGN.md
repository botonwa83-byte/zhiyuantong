# 分批次志愿填报：数据调查与设计方案

> 调查时间 2026-09-20，数据基准 2025 年录取数据（内置于 App）。目标：让 2027 届考生能在**提前批 / 本科批 / 专科批 / 专项批 / 征集批**各自拿到合理的智能志愿表。

## 一、结论摘要

1. **数据里本来就有批次**：`staging/admission.csv` 67189 行**全部带 `batch` 字段**，29 个省共 58 种批次写法。
2. **但导出时丢了，而且跨批次取了最低分**（已修，见第三节）：一所院校同时有本科批与专科批时取最小值，等于拿专科线当院校线——3628 组受影响，**2614 组分差 ≥ 30 分，最大 108 分**（河北科技工程职业技术大学 本科批 500 / 专科批 392）。冲稳保判断会整体失真。
3. **征集志愿（补录批）数据完全没有**：投档线表里只有正式投档，征集志愿的降分录取不在其中，只能靠规则提示 + 后续补源。

```

含「提前/零志愿」 → 本科提前批
含「本科/一段/一批/二批」 → 本科批
```

关键差异：

- **志愿数从 18 到 112 不等**：辽宁本科批 112 个「专业+学校」最多，新疆各批 18 个最少，主流是 45（院校专业组）与 96（专业+院校）。河南本科批 48 个，全国唯一。
- **有没有专业调剂**：河北、山东、辽宁、重庆、贵州、青海、浙江是「专业（类）+学校」，**没有专业调剂**，每个志愿都必须能接受；其余省是「院校专业组」，组内可调剂。
- **顺序（梯度）志愿**：四川本科提前批 A 段（1 个第一志愿 + 2 个平行第二志愿）、辽宁提前批 A 段与专科提前批（2 个有序院校志愿）、新疆各批（梯度志愿）都是第一志愿优先，冲稳保比例不能照搬平行志愿。
- **分段投档**：山东常规批一段/二段、浙江普通类一段/二段、天津本科批 A/B 段、四川本科批 A/B 段，前一段录完才开下一段。
- **录取顺序**：前一批次被录取，后续批次志愿自动作废；提前批各类（军事/公安/司法/师范/医学）基本都规定不得兼报。

## 五、缺口与风险

- [ ] **征集志愿（补充批）没有数据**：投档线表只含正式投档。征集志愿的院校、缺额、降分幅度各省考试院在录取期间才逐批公布 → 短期只能做"提醒 + 经验降分"，长期需要新增数据源或人工录入模板。
- [ ] **提前批的规则差异没进数据**：军事 / 公安 / 司法 / 师范 / 医学各类不得兼报、需要体检政审面试——志愿表必须按"类"分开给，不能混在一个列表里。
- [ ] **专项批资格**（国家 / 地方 / 高校专项的户籍学籍门槛）需要考生档案增加字段，否则会把够不着的院校推荐给考生。
- [ ] **顺序志愿 vs 平行志愿**：四川提前批 A 段、部分省提前批是顺序志愿，第一志愿没录上会大幅掉档，冲稳保比例不能照搬平行志愿（平行冲 30%，顺序志愿第一志愿要放在"稳"）。
- [ ] **志愿数上限各省不同（5 ~ 96）**：生成算法必须按省裁剪，不能固定 30 个。
- [ ] 源数据缺清华、北大等顶尖院校投档线，这些院校目前只能走模型推算。

## 六、设计方案（阶段二已完成，阶段三待实施）

### 阶段二：批次规则进数据集（已完成）

落地文件：`ZhiYuanTong/Scripts/data/batches.ts`（31 省）+ `Scripts/export-data.ts` 装配进 `bundle.json`（键 `batchRules`，导出时校验省份存在、必含本科批与专科批、order 不重复）+ Swift `BatchRuleDTO` / `ProvinceBatchesDTO` / `DataStore.batches(of:)` + `fillableBatches`（按分数筛可填批次）与 `tierQuota`（冲稳保按志愿数分配，顺序志愿不冲）。数据结构：

新增 `ZhiYuanTong/Scripts/data/batches.ts`（导出进 bundle.json）：

```ts
export interface ProvinceBatch {
  provId: string
  batches: Array<{
    kind: 'earlyUG' | 'undergrad' | 'special' | 'earlyCollege' | 'college' | 'supplement'
    name: string            // 省里的官方名称，如「本科提前批」「普通类一段」
    order: number           // 录取顺序
    maxVolunteers: number   // 志愿数上限（河南本科批 48 / 河北 96 / 广东 45）
    mode: 'parallel' | 'sequential'   // 平行 / 顺序志愿
    unit: 'group' | 'major'           // 院校专业组 / 专业+学校
    allowAdjust: boolean              // 是否有专业调剂（河北无调剂）
    note?: string                     // 兼报限制、体检政审等提示
  }>
}
```

按上面的官方规则先填河南、山东、河北、四川、广东、浙江、江苏、安徽、湖北、湖南、江西（考生大省），其余省先用"本科批 45 / 专科批 45 平行志愿"的保守默认并标注待核对。

### 阶段三：App 按批次生成志愿表（已完成）

数据层

- `VolunteerItem` 新增 `batch`（`BatchKind.rawValue`），旧存档解码缺失按本科批归组，不会丢志愿表。
- `buildBatchAdmissionIndex` / `findBatchAdmission`：按「省份+科类+年份+批次+院校」建索引，同一批次多条取最低分。
- `Engine.buildRecords(provId:track:batch:)`：指定批次时**只收录该批次有投档线的院校** —— 该批次没在我省招生的学校，志愿表里根本填不进去。
- `AppState`：`currentBatch`、`availableBatches`（按分数筛掉填不了的批次）、`evals(for:)`、`selectBatch`、`batchEvals`；`generateVolunteers` **只替换同批次志愿**，本科批与专科批分别生成、互不影响。

生成层（Recommend）

- `GenPrefs` 新增 `batch` 与 `rule`；`planCounts` 用 `tierQuota` 按该省志愿数上限分配（辽宁 112、河南本科批 48、四川提前批 A 段 3），顺序志愿冲 = 0。
- 生成时按批次给提示：顺序/梯度志愿第一志愿优先、提前批各类不得兼报且录取后后续批次作废、专业+学校无调剂、志愿数上限待核对、征集志愿提醒、A/B 段共用投档线数据（四川本科批 A/B、辽宁提前批 A/B 源数据未分段，志愿会重复，已明确提示）。

界面

- 生成向导新增第 0 步「填报批次」：列出该省可填批次（志愿数、平行或顺序、志愿单位、待核对标记）。
- 志愿表页：批次切换（带各批次已填数量）、批次规则卡（n/max、模式、单位、调剂）、提前批类别卡、征集志愿提醒卡。
- 体检新增：超出批次上限、顺序志愿里放了冲刺志愿；「服从调剂」在专业+学校模式显示「无此选项」。

仍存在的缺口（不再属于阶段三范围）

1. **征集志愿（补录批）无数据** —— 只有提示卡，考生需盯省考试院公告。
2. **专项批（国家/高校/地方专项）没有资格字段** —— 现在按批次生成但不验证资格，需考生自查。
3. **四川本科批 A/B 段、辽宁提前批 A/B 段共用同一批投档线** —— 源数据没分段，生成结果会重复（已提示）。
4. **28 个批次的志愿数上限尚未逐条核对官方文件**（在 App 内标 ⚠️），考生大省建议复核。
5. 提前批需要体检/政审/面试的具体条件不在数据里，只有类别提示。

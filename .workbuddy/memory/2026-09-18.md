# 2026-09-18

## 评估 gaokao 项目能否用 Xcode 编译

用户目标：把项目做成 iPhone / iPad / Mac 应用，想确认能否直接用 Xcode 编译。

### 结论
不能。项目是纯前端 Web 栈（React 18 + TS + Vite 7 + Tailwind 3），
`npm run build` 产出 `dist/index.html` + `assets/index-*.js`(329KB) + `assets/index-*.css`(23KB)。
Xcode 27.0 已装在本机，但只认 Swift/ObjC/C++，无 JS/TS 工具链。

### 三条可行路线
1. **WKWebView 外壳**（最轻）：Swift 壳 + 把 dist 作为 bundle 资源加载。
2. **Capacitor**（推荐）：`npx cap add ios` 自动生成 `ios/App/App.xcodeproj`。
3. **PWA**：不加 Xcode，index.html 已有 `apple-mobile-web-app-capable` 等 meta。
Mac 覆盖：方案1 需加 Mac Catalyst 或独立 macOS target；方案2 在 Xcode 勾 Support Mac Catalyst；
Apple Silicon 可直接用 "Designed for iPad"；PWA 在 macOS Sonoma+ Safari 添加到程序坞。

### 已发现的两个具体阻塞点（未修改代码）
- `vite.config.ts` 未设 `base: './'`，产物里是 `/assets/...` 绝对路径 → 本地文件加载会白屏。
- 项目重度依赖 `localStorage`（`src/lib/storage.ts` 账号/会话、`src/lib/dataset.ts` 官方数据集）。
  WKWebView 走 `file://` 时 origin 为 opaque，localStorage 不可靠；
  需改用 `WKURLSchemeHandler` 自定义 scheme，或直接走 Capacitor 的 `capacitor://localhost`。

### 有利条件
项目零 `fetch`、零后端依赖、导航用 `useState` 而非 react-router、
无 `window.location` 跳转 —— 套壳几乎不需要改造网络层。
